## 现在的排布

- Open：打开调用 → 结果 → 节点描述 → 其余。打开采样前缀没变，推理保留。
- Next：上一节点 memory → next 调用（去推理、去签名）→ 结果 → 新节点描述。next 采样属于新节点，同一步的 read 结果保留。
- Close：关闭采样随节点折叠，关闭后只剩 memory〔摘要，节点里保留的用户消息、回复、arrival，按记录顺序〕。spine_close 和别的工具同一步调用时返回工具错误，要求单独再调。
- 保留的回复：去推理（原 `Reply` 标签，同一条规则）。

## 两条规则的核实

- 规则 1（Gemini）。重放 10-29 的失败请求 004（各 3 次）：描述挪到调用和结果之后 3/3；再把被挪的那次模型输出去掉思考和签名 3/3；所有旧轮都去掉 3/3；原排布下把当前轮那次调用去签名 0/3（直接 400）。和文档一致：只校验当前轮，旧轮缺签名不报错。DSH 实测请求里核过：next 调用回放不带签名、open 调用保留签名、关闭调用不再出现。
- 原定 Close 排布「关闭调用 → 结果 → memory」做不出来：memory 里保留的原消息在 DSH 日志里记在关闭调用之前，DSH 的 surface 只能按日志顺序显示原消息。把摘要放到最后能满足 DSH，但和 9e956ba 的实测冲突（摘要在后时 Gemini 0/5 去调工具）。经请示（/close-layout），用户定 A 试行。
- 规则 2（Claude）。文档（preserved thinking）：签名绑定 system、tools、块前的每条消息，并链到上一个 thinking 块；整块去掉 thinking 合法，文档对 keep-tail 压缩明确写「去掉保留轮次的 thinking 块，文字和工具调用可以留」，条件是去掉的块之后的块都是去掉之后才生成的。Spine 在下一次请求前就去掉，之后每次渲染都一样（rules 由节点结构决定，replay 测试核过同一份上下文），满足这一条。实测没做成，见下。
- 各路径：
  - spawn：spawn 采样留在父节点，birth 排在它之后，前缀不变，推理保留。没改。
  - arrival：在两次采样之间进入游标节点，不在采样内部。没改。
  - kept reply：随 Close 留在 memory，去推理。测试钉住。
  - resume/fork：上下文由同一个 reducer 从记录重放得出；内核 `history.replay()` 核对实时与重放一致；DSH 去推理用一条插件记录 + message projection，恢复和 fork 时重算。DSH 的 resume 测试全过。
  - compact：新 epoch 只保留压缩结果，旧采样不带过来；没改，也没专门测。
